# m0-crypto proofs

Lean 4 proofs that the released machine code of [m0-crypto](../README.md) computes ChaCha20, Poly1305 and ChaCha20-Poly1305 as specified in RFC 8439. This repository is the `proofs/` submodule of the library and is not meant to be used on its own.

## Check

From the library checkout (with submodules):

```sh
proofs/tools/check.sh
```

Needs Lean v4.35.0 (via `elan`), LLVM/LLD 23.1.4 and QEMU 11.1.3. Set `M0C_LIB` if the library is not the parent directory. The script:

1. builds the library and checks that its `.text` equals
   `lean/M0Crypto/Artifacts/Release.lean` (3030 bytes,
   sha256 `b85f137f8356ea1d290578ce03616b3e00cff08aac7cc1104b3e9fdadfc990d3`);
2. builds every proof with `lake build`, including executions of the artifact in the
   model against the RFC 8439 specification;
3. checks that the model's decoder agrees with `llvm-objdump` on every instruction;
4. rejects `sorry`, new axioms and unlisted dependencies (`lean/Audit.lean` lists the
   audited theorems; `tools/statements.golden` locks their statements);
5. runs the library's QEMU tests.

`tools/mutate_aead.py` applies deliberate bugs to the assembly and confirms that the tests or the model checks detect each one.

## Contents

- `lean/M0Crypto/Spec`: RFC 8439 specification.
- `lean/M0Crypto/Armv6M`, `Thumb`: the ARMv6-M model (decoder and executor).
- `lean/M0Crypto/Artifacts`: the machine code under proof (generated by
  `tools/extract_release.py`).
- `lean/M0Crypto/Release`: the proofs. Entry points: `M0Crypto.Release.ChaChaXor.chacha20_xor_correct`,
  `M0Crypto.Release.Aead.encrypt_correct`, `M0Crypto.Release.Aead.decrypt_correct`.
- `fixtures/`, `link/`: standalone ChaCha fragments used by early proof stages.

## Implemented proofs

The functional proofs connect the release bytes to RFC 8439 and establish:

- ChaCha20 output and counter-overflow rejection.
- Poly1305 modular arithmetic and init → blocks → finish composition.
- AEAD ciphertext and authentication tags.
- Checked decryption, verification before writes, and unchanged output on failure.
- Confined writes, restored SP and callee-saved registers, and the working-stack
  clearing specified by the function contracts.

The proofs cover any buffer length, byte alignment, and in-place calls (out == in). Preconditions are standard: buffers cannot wrap around memory, cannot partially overlap, and need enough stack space. When returning, the code restores all caller registers and wipes secret working data from the stack.

The ARMv6-M model describes ordinary byte-addressed memory without interrupts, concurrent memory changes, peripherals or injected faults. Its decoder is checked against LLVM and its execution is tested against specification vectors.

## Roadmap

Constant-time trace proofs, read-address bounds and intermediate stack-pointer bounds are planned for a later release. `Release/TraceSpec.lean` defines these properties.

Power-analysis and fault-injection resistance are outside the release scope.
