## B3. Specification

**Check against:** [RFC 7693](https://www.rfc-editor.org/rfc/rfc7693) (§2.1 parameters,
§2.6 IV, §2.7 SIGMA, §3.1 G, §3.2 F, §3.3 padding and digest).

- [ ] Each definition against its RFC section, in the RFC's own order.
- [ ] Constants digit by digit: IV, SIGMA, `0x01010020`.
- [ ] The vectors in [`Spec/Blake2sVectors.lean`](lean/M0Crypto/Spec/Blake2sVectors.lean)
      come from RFC 7693 Appendix B and from Python `hashlib`, not from this spec. They are
      `#guard` evaluations: tests, not kernel proofs.
- [ ] The streaming state (`State`, `push`, `absorb`, `finish`) is not in the RFC: it is a
      design choice and must match the header.

A spec bug on a path the vectors do not exercise passes all of them, for example the byte
counter above 2^32.

## B4. Contracts and statements

Same questions as `REVIEW.md` section 3.5. **Check against:**
[`include/m0crypto/blake2s.h`](../include/m0crypto/blake2s.h) for the public entries,
[`src/blake2s_internal.h`](../src/blake2s_internal.h) for `compress`, `copy` and the
context offsets, and claims C1-C4 in the plan (`docs/design/blake2s-proofs.md` §1 in the
dev repository).

Specific points:

- [ ] `Ctx` offsets equal the `_Static_assert`s in `blake2s_internal.h` (h 0, count 32, buf 40, used 104).
- [ ] `hash_machine` assumes that every call returns (`hruni`, `hrunf` and the run inside
      `Calls`). It is a *partial correctness* statement: "if each call returns, the digest is
      correct". The per-call theorems (`init_correct`, `update_correct`, `final_correct`)
      do prove termination (`∃ n, ∀ fuel ≥ n, runUntil … = .ok …`), so the gap is only in
      the composed statement. The hypotheses also name each call's return state; when C1 is
      locked, decide whether to derive them from the per-call theorems instead.
- [ ] `compress`'s `Entry` limits `f0` to 0 or 0xffffffff. `blake2s_internal.h` requires
      the same; the code itself XORs any value into v14, but only these two are proved.
- [ ] `CtExtra` is assumed by `compress_constant_time` and by `compress_stack`.
- [ ] The stack preconditions ask for more room than the frames use (`spLo`: 176 for
      `compress`, 200 for `update` and `final`, against frames of 136 and 160 bytes). Check
      that this only rules out a stack at the very bottom of the address space.
- [ ] This list is incomplete until the constant-time, read and stack statements for `init`,
      `copy`, `update` and `final` exist. If one of them takes a list of public loads as a
      hypothesis (`Env.pubLoads` in the certificate checker), that list becomes trusted.

## B5. Non-vacuity

[`Release/NonVacuity.lean`](lean/M0Crypto/Release/NonVacuity.lean) has witnesses for the
entry contracts of `compress`, `init`, `update` and `final`, each passed to its correctness
theorem. [`copy_correct_nonvacuous`](lean/M0Crypto/Release/Blake2sCopyMain.lean#L232) covers
`copy`. Missing: a witness for `CtExtra` (so `compress_constant_time` and `compress_stack`
are not instantiated), and a witness for `hash_machine`, whose hypotheses are implications
and so carry the highest risk of being unsatisfiable. None of the BLAKE2s witnesses is in
`Audit.lean`.

## B-open. Constant-time public registers (found by the phase D review, 2026-11-11)

Every BLAKE2s constant-time theorem and `PubEq` (hence `C4`) treat r0-r3 as public for every
entry (`ConstantTime/EntriesDefs.lean`, `entryRegs`), as the ChaCha20 and AEAD theorems do.
`init` takes one register argument, `update` and `copy` three, `final` two. A caller that leaves
a secret-dependent value in an unused one of r1-r3 is outside the theorem. The code is not
affected as far as the listing shows (`init` writes r1-r3 from literals, `final` loads r2/r3
before use), but the proof does not say so. Closing it needs per-entry public-register counts
in `entryState`, `entryState_sound` and `PubEq`, and regenerated certificates.

**Closed 2026-11-11.** `entryStateP np`, `entryStateP_sound`, `PubEq np`; init 1, final 2, update/copy 3, compress 4. Certificates regenerated; full build, Audit, statements golden and check.sh pass.
